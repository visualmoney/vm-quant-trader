# ADR-0013: 실전 계좌 승격은 자동 검증 7항 + 수동 확인 5항을 통과해야 한다

| 항목 | 내용 |
| --- | --- |
| 상태 | **채택됨 (Accepted)** — 기준 확정·검증 도구 구현 (2026-08-20) |
| 작성일 | 2026-08-20 |
| 맥락 | [spec/kis-broker-design.md](../spec/kis-broker-design.md) §11 Q8 |
| 관련 요구 | FR-15·FR-19, A-1~A-5 ([spec/kis-broker.md](../spec/kis-broker.md)) |

## 맥락

인수 기준 A-1~A-5는 **모의투자까지만** 요구하고, 실전(`prod`) 전환은 별도 판단 사안으로 남아 있었다(Q8). 남겨 둔 방어는 하나뿐이었다 — `svr='prod'`를 코드에 **명시해야만** 실전에 닿는다는 것.

그 방어는 실수로 실전에 연결되는 것을 막을 뿐, **준비되지 않은 채 의도적으로 연결하는 것**은 막지 못한다. 그리고 이 프로젝트에서 실전 전환은 **되돌릴 수 없는 유일한 행동**이다 — 백테스트는 다시 돌리면 되고 모의투자는 잃을 것이 없지만, 실전 주문은 체결되면 끝이다.

**기준을 문서로만 두면 지켜지지 않는다.** 사람은 승격하고 싶을 때 승격하며, 그때 체크리스트는 읽히지 않는다.

## 결정

**승격 기준을 확정하고, 기계가 확인할 수 있는 것은 기계가 확인한다.** 검증 도구는 `scripts/promotion_check.py`이며, 모의 운용이 남긴 원장을 읽어 판정한다.

### 자동 검증 7항 (원장에서 확인)

| 기준 | 근거 |
| --- | --- |
| **days-run** — 20거래일 이상 운용 | 나쁜 날을 한 번도 겪지 않은 배치는 나쁜 날에 대해 아무것도 증명하지 못했다 |
| **orders-placed** — 실제 접수된 주문이 있다 | 한 달을 돌았어도 거래하지 않았다면 거래에 대해 증명한 것이 없다 |
| **fills-booked** — 체결이 회계에 반영됐다 | 접수만으로는 회계 경로가 검증되지 않는다 |
| **no-orphan-intents** — 주문번호 없는 의도가 남아 있지 않다 | 그 주문의 생사를 아무도 확정하지 않았다는 뜻이다. **포지션을 모르는 채 승격하는 것**이다 |
| **stale-ratio** — STALE 비율 20% 이하 | 만성 미체결은 시간 예산이나 리밸런싱 시각이 틀렸다는 신호이고, 실전이 그것을 그대로 물려받는다 |
| **no-duplicate-fills** — 멱등키 중복 0 | 제약이 실제로 걸려 있었는지 확인한다(구 스키마로 만든 원장에는 없다) |
| **kill-switch-exercised** — 킬스위치가 최소 1회 발동됐다 | **한 번도 당겨 본 적 없는 안전장치는 작동을 아무도 모르는 안전장치다** |

### 수동 확인 5항 (사람만 판단 가능)

1. 모의투자 스모크 **A-3·A-4·A-5** 통과 (#27)
2. **실전 주문 한도와 초기 자본** 합의 — 특별한 이유가 없다면 모의 값보다 **낮게**
3. **수동 청산 경로 예행** — 이 엔진 없이 계좌를 정리할 수 있는가
4. **토큰 발급 주체 확정** — KIS는 동일 APP_KEY의 **60초 내 재발급을 거부**한다. 다른 봇과 앱키를 공유하면 본 엔진은 **발급자가 아니라 소비자**여야 한다
5. **첫 실전일에 사람이 지켜본다**

## 검토한 대안

| 대안 | 기각 사유 |
| --- | --- |
| 1. 문서 체크리스트만 둔다 | 승격하고 싶은 순간에 읽히지 않는다. 기계가 확인할 수 있는 것을 사람 기억에 맡기는 것은 낭비다 |
| 2. 코드로 `prod`를 봉인하고 승격 시 해제 | 봉인 해제 커밋이 곧 체크리스트 통과의 증거인 척하게 된다 — 실제로는 아무것도 검증하지 않는다 |
| 3. 전부 자동 검증 | 수동 청산 예행이나 한도 합의는 **데이터베이스에 나타나지 않는다.** 자동화할 수 없는 것을 자동화한 척하면 그 항목이 조용히 사라진다 |

## 근거

**자동과 수동을 명시적으로 갈랐다.** 도구는 자동 7항을 판정하고, 통과해도 *"승격에는 아래 수동 항목이 여전히 필요하다"*고 출력한다. 자동 검증이 승인 도장처럼 읽히면 수동 항목이 증발하기 때문이다.

**원장이 증거다.** 별도의 운용 일지를 요구하지 않는다 — 운용하면 남는 것으로만 판정하므로, 증거를 만들기 위한 추가 작업이 없다.

**60초 재발급 규칙은 실측이다.** 운용 호스트의 기존 봇들이 이미 이 문제를 겪고 "발급 주체 하나 + 나머지는 소비자"로 정리했다. 본 엔진이 같은 앱키로 토큰을 새로 발급하면 **가동 중인 실계좌 봇의 토큰을 깨뜨릴 수 있다.**

## 결과

- `scripts/promotion_check.py`는 원장을 **읽기 전용**(`mode=ro`)으로 연다. 점검이 배치를 바꿀 수 없다.
- 자동 기준 미달 시 종료 코드 1을 반환하므로 cron이나 CI에 걸 수 있다.
- **20거래일**은 임의값이다(`--min-days`로 조정). 근거는 "월간 리밸런싱 전략이라도 한 사이클은 겪는다" 정도이며, 실측으로 바뀔 수 있다.
- 이 ADR은 승격을 **허가하지 않는다.** 기준을 정할 뿐이고, 통과 여부는 모의 운용이 쌓인 뒤에 판정된다.
