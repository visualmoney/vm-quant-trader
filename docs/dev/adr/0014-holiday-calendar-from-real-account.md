# ADR-0014: 휴장일 캘린더는 실전 계좌에서 받아 파일로 캐시한다

| 항목 | 내용 |
| --- | --- |
| 상태 | **채택됨 (Accepted)** — 구현·실측 완료 (2026-08-20) |
| 작성일 | 2026-08-20 |
| 맥락 | [spec/kis-broker.md](../spec/kis-broker.md) C-6·§8, 이슈 #51 |
| 관련 요구 | FR-9, NFR-1·NFR-3 |

## 맥락

`KrxExchange`는 처음부터 휴장일을 **주입받는** 구조였고(FR-9), 조달처는 KIS `chk_holiday`로 정해져 있었다. 그런데 Phase 3 스모크에서 실측하니 **모의투자 서버가 이 엔드포인트를 제공하지 않는다** — `OPSQ0002 없는 서비스 코드`(2026-08-20).

휴장일을 모르면 주말만 걸러지고 **공휴일에 주문을 시도한다.** ADR-0013의 20거래일 증거가 매번 깨끗하게 쌓이지 않는다.

사용자 판단: *"실제 거래가 아니고 휴장일 값을 실전 계좌에서 획득해도 문제없다. 자산의 변동이 없다."* 이 판단은 **옳다** — `chk_holiday`는 순수 조회이고 주문 경로와 무관하다. 다만 실측으로 두 가지가 더 드러났다.

| 실측 | 내용 |
| --- | --- |
| 토큰은 재사용된다 | `kis_auth.auth()`는 유효한 캐시 토큰이 있으면 **재발급하지 않는다**(`kis_auth.py:212`). 실전 조회가 동거 봇의 토큰을 깨뜨릴 위험은 크지 않다 |
| **그러나 토큰 캐시 파일명이 서버를 구분하지 않는다** | `~/KIS/config/KIS<날짜>` 하나뿐이다. 같은 날 실전으로 인증하면 이후 모의 세션이 **실전 토큰을 읽어** 실패한다 |

## 결정

**실전 계좌로 조회하되, 별도 프로세스가 자기 `HOME`을 갖고 실행하며, 결과는 파일로 캐시한다.**

| 항목 | 규칙 |
| --- | --- |
| 조달 | `scripts/fetch_holidays.py` — `chk_holiday` **외의 호출은 하지 않는다**. 주문 경로 없음 |
| 서버 | `prod`. 이 엔드포인트는 실전만 답한다 |
| **토큰 격리** | 자기 `HOME`(`~/.vmtrader/holiday-home`)을 설정하고 자격증명을 **복사**해 넣는다(심볼릭 링크 금지 — 토큰이 링크를 타고 원본 디렉터리에 쓰이면 안 된다). 실전 토큰이 모의 배치가 읽는 경로에 남지 않는다 |
| 캐시 | JSON(`start`·`end`·`holidays`·`open_days`). 엔진은 `load_holidays(path)`로 읽어 `KrxExchange(holidays=...)`에 넘긴다 |
| 범위 검사 | `holiday_file_covers(path, dt)` — **범위가 지난 캘린더는 없느니만 못하다**. 끝난 뒤의 모든 날이 개장일로 보이기 때문이다 |
| 주기 | 1일 1회(KIS 권고). 토큰 cron(08:20)과 겹치지 않는 시각에 |

## 검토한 대안

| 대안 | 기각 사유 |
| --- | --- |
| 1. 정적 목록 (연 1회 수기 갱신) | 임시 휴장·조기종료를 놓치고, 갱신을 잊으면 조용히 틀린다. 사람의 기억에 의존하는 안전장치다 |
| 2. `exchange_calendars` 패키지 | 신규 런타임 의존이 생기고, 그 패키지의 KRX 캘린더가 **거래 상대의 캘린더와 일치한다는 보장이 없다.** 권위는 거래소가 아니라 우리가 주문을 내는 곳에 있다 |
| 3. 매 세션마다 실전 조회 | KIS가 1일 1회를 권고하고, 세션마다 실전 인증을 하면 토큰 충돌 표면이 매일 두 번으로 늘어난다 |
| 4. 모의 계좌로 조회 | **불가능하다** — 서버가 엔드포인트를 제공하지 않는다 |

## 근거

**"자산 변동이 없다"는 판단이 옳고, 실제 위험은 다른 축에 있었다.** 걱정할 것은 우리 주문이 아니라 **동거 실계좌 봇과의 토큰 경합**이었고, 그것은 프로세스에 자기 `HOME`을 주는 것으로 구조적으로 사라진다 — 우리 토큰이 그쪽이 보는 디렉터리에 아예 도달하지 않는다.

**파일이 호출보다 낫다.** 거래소 캘린더는 하루에 여러 번 바뀌지 않으므로 매 기동 조회는 낭비이고, 파일이면 **거래소가 응답하지 않아도 세션이 돈다**.

## 결과

- 실측 (2026-08-20): 400일 요청 → **휴장 130일 · 개장 271일**, 2026-08-20 ~ 2027-09-24 커버. 개천절·성탄절·신정·삼일절 모두 휴장으로 확인.
- **토큰 격리 실증**: 실행 후 모의 토큰 캐시(`~/KIS/config/KIS20260820`)가 **변경되지 않았고**, 실전 토큰은 격리 홈에만 생성됐다.
- 구현 중 잡은 결함: 거래소가 요청 범위 **너머까지 응답**하는데 그 날짜를 커버 범위에는 넣고 휴장일 수집에서는 제외하고 있었다 → 파일이 **검사한 적 없는 날을 커버한다고 주장**하게 된다. 범위 검사가 잡으려던 바로 그 상황이라 수정했다.
- 남는 것: 실전 자격증명이 호스트에 있어야 한다. 이 호스트에서는 동거 봇이 이미 쓰고 있어 새로 생기는 노출은 없다.
